What is a computer program?

A program is an exact list of instructions for the computer. The computer follows them one by one, perfectly, with zero guessing. If you say "print hello" it prints hello. If you say nothing it does nothing. Python is the language we use to write those instructions — famous for reading almost like English.

🧩 Analogy: Imagine a pet robot that only speaks "Python". You write instructions, the robot reads and obeys. Your file (.py) is the instruction manual. The robot never improvises — it does exactly what you wrote, even if what you wrote is wrong!
program = instructionsPython = the languageIDLE = where we write.py = our filerun = execute the instructions

print() — making Python speak

print() is a command (called a function). Whatever you put inside the brackets and quotes gets shown on screen. The quotes say "this is text, not a command". No quotes → Python thinks it's a variable name and gets confused.

Show this error deliberately: print(Hello) → NameError: name 'Hello' is not defined. Fix: print("Hello"). Every beginner makes this. Errors are clues — always read the last line first.

Variables — labelled boxes in memory

Computer memory is a wall of boxes. Each box holds one value. A variable is the label on a box. name = "Aryan" creates a box, puts "Aryan" in it, sticks "name" on it. Write name later and Python fetches what's inside.

Three data types to know today: str (text in quotes), int (whole number, no quotes), float (decimal, no quotes). Use type() to check what you have.

🧩 Analogy: Your school bag has labelled pockets — "books", "lunch", "pencils". Variables are those pockets. You label them, put things in, take things out, swap contents any time. The label stays; only what's inside changes.
Classic mistake: age = "11" looks right but "11" is text — you can't do math! age = 11 (no quotes) makes it a number. Demo both: age = "11" then print(age + 1) → TypeError. age = 11 then print(age + 1) → 12.

input() — making programs interactive

Until now all data was hardcoded. Real programs ask the user. input() pauses, shows a prompt, waits for the user to type and press Enter, then stores what they typed as a string.

Critical: input() ALWAYS returns a string — even if the user types 42. To do math, convert first: int(input(...)) or float(input(...)). This is the #1 beginner mistake worldwide.

🧩 Analogy: input() is a question box on a form. The text in quotes is the label on the box. The user writes their answer and hits Enter. Python stores it. If it's a number and you need to do math — wrap it in int() like a conversion machine.
Show this error deliberately: age = input("Age: ") then print(age + 1) → TypeError. Must use age = int(input("Age: ")). Demo: type 11 when asked, watch it fail, add int(), watch it work. This error appears more than any other in beginners' code.

Booleans — Python's yes and no

A boolean has exactly two values: True or False. Every comparison produces a boolean. 5 > 3 → True. 10 == 5 → False. The computer uses these True/False results to decide which code to run.

== equal to!= not equal> greater than< less than>= greater or equal<= less or equal
Most common mistake in Python forever: = assigns a value. == checks equality. Writing if x = 5 is a SyntaxError. Must be if x == 5. Burn this into memory — show the error deliberately every time.

if/else — Python picks a path

if: condition True → run this block. else: condition False → run that block instead. Exactly ONE branch ever runs. Indentation (4 spaces) tells Python which lines belong inside the block — it's not optional, it's the rule.

🧩 Analogy: A fork in the road. Python reads the sign (condition). If True, takes the left road. If False, takes the right road. Both roads lead forward — but through different territory. Only one road is ever walked.

elif — more than two paths

if/else gives two choices. elif (else if) chains multiple conditions. Python checks them TOP TO BOTTOM, finds the FIRST True one, runs that block, skips ALL others — even if later conditions would also be True.

🧩 Analogy: A restaurant menu check: "Veg meal? No → Chicken? No → Fish? No → Default meal." Python stops at the first yes. Order of your elif matters enormously.

and, or, not — combining conditions

and — both must be True: age > 10 and age < 18 (teenager check)

or — at least one True: color == "red" or color == "blue"

not — flips True↔False: not is_raining

These let you ask complex questions in a single if without nesting.

Nested if — conditions inside conditions

Put an if inside another if. The inner if only runs if the outer if's condition was True. Each nesting level adds 4 more spaces. Python knows which level you're at by counting indentation.

🧩 Analogy: "IF you're at school → IF you finished homework → free period. ELSE → detention." The homework check only matters if you're actually at school first.

String comparisons + the "in" keyword

"Yes" ≠ "yes" ≠ "YES" in Python. Always use .lower().strip() on user input before comparing so any capitalisation works.

The in keyword checks if something exists inside something else: "py" in "python" → True. "mango" in ["apple","mango","banana"] → True. Very useful!

for loops — when you know what you're looping through

A for loop runs a block of code once for each item in a sequence. You use it when you know exactly what you're looping through — a range of numbers, every letter in a word, every item in a list.

range(5) → 0,1,2,3,4. range(1,6) → 1,2,3,4,5. range(0,10,2) → 0,2,4,6,8. The END number is NEVER included — beginners always forget this.

🧩 Analogy: "For each student in the classroom, give them a textbook." You go through every student in order, doing the same thing. A for loop is exactly this — go through a defined set, perform the same action on each one.
range(n) → 0 to n-1range(a,b) → a to b-1range(a,b,step)for x in collection:accumulator = 0 before loop

Theory (0–8 min)

while loops — when you DON'T know how many times

while keeps running as long as a condition is True. You use it when the number of repetitions depends on what happens at runtime — like "keep asking until the user gets it right."

break exits the loop immediately. continue skips the rest of this iteration and goes back to the top. Always make sure your while loop can eventually stop — an infinite loop freezes the program!

🧩 Analogy: A turnstile at a metro station. WHILE there are passengers coming through, keep spinning. You don't know in advance how many passengers there will be. You only stop when they stop coming (or break is called).

Lists — storing multiple values in one variable

A list holds multiple values in order: fruits = ["apple","mango","banana"]. Access by index (starting at 0): fruits[0] → "apple". fruits[-1] → last item. Key methods: .append(x), .remove(x), .pop(), len(list), x in list.

IndexError demo: Try fruits[10] on a 3-item list → IndexError: list index out of range. Indices run from 0 to len(list)-1. Show fruits[-1] as a safe way to get the last item without knowing the length.

Theory (0–8 min)

List slicing — extracting parts

list[start:end] extracts from start up to (not including) end. list[:3] = first 3 items. list[2:] = from index 2 to end. list[-2:] = last 2 items. list[::-1] = the entire list reversed! The same syntax works on strings.

🧩 Analogy: Slicing a loaf of bread. "Give me slices 2 to 5." You don't take the whole loaf — just the portion you need. The original loaf is unchanged.

Powerful built-in list functions

min(list) → smallest · max(list) → largest · sum(list) → total · sorted(list) → new sorted copy · list.count(x) → how many times x appears · list.index(x) → position of first x

These work on any list of numbers. sorted() returns a NEW list — the original is untouched. list.sort() modifies the original in place.

Theory (0–8 min)

Functions — reusable named blocks of code

A function is code you write once and call many times by name. Parameters are inputs you pass in. The return value is what it gives back. Without return, the function gives back None.

🧩 Analogy: A vending machine. You put in coins (parameters), press a button (call it), get a snack (return value). You don't care how it works inside — you just use it.
Scope: Variables created inside a function only exist while that function runs. They vanish after. This is called local scope. Demo: create x inside a function, try to print x outside → NameError.

import random def get_computer_choice(): return random.choice(["rock","paper","scissors"]) def get_player_choice(): while True: c = input(" Move (rock/paper/scissors/quit): ").lower().strip() if c in ["rock","paper","scissors","quit"]: return c print(" ⚠ Invalid!") def decide_winner(p, c): if p == c: return "tie" return "player" if (p,c) in {("rock","scissors"),("paper","rock"),("scissors","paper")} else "computer" def get_verdict(ps, cs): if ps > cs: return "🏆 You dominated!" elif cs > ps: return "🤖 Computer wins overall!" else: return "🤝 Perfect tie!" def play(): sym = {"rock":"🪨","paper":"📄","scissors":"✂️"} name = input("Your name: ") print(f"\n🎮 Welcome {name}! Type 'quit' to stop.\n") ps, cs, ts, streak, history = 0, 0, 0, 0, [] rnd = 0 while True: rnd += 1 print(f"--- Round {rnd} ---") player = get_player_choice() if player == "quit": break comp = get_computer_choice() w = decide_winner(player, comp) print(f" {sym[player]} vs {sym[comp]}") if w == "player": ps += 1; streak += 1 print(f" 🎉 {name} wins!" + (f" 🔥{streak} streak!" if streak>=2 else "")) elif w == "computer": cs += 1; streak = 0; print(" 💻 Computer wins!") else: ts += 1; streak = 0; print(" 🤝 Tie!") history.append(f"R{rnd}: {player} vs {comp} → {w}") print(f" Score: {name} {ps} | CPU {cs} | Ties {ts}\n") total = ps + cs + ts print("="*35) print(f" FINAL — {total} rounds") print(f" {name}: {ps} CPU: {cs} Ties: {ts}") if total: print(f" Win rate: {round(ps/total*100)}%") print(f" {get_verdict(ps,cs)}") print("\n History:") for h in history: print(f" {h}") print("="*35) play()
